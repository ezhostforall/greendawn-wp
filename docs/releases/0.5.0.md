# Candidate v0.5.0 — header, navigation, layout and typography

**Status: prepared in source; not yet published or installed.** The merged foundations in PRs #34 and #35 need hosted staging acceptance before footer development continues. v0.4.1 remains approved stable. Existing tags and release assets are unchanged.

This candidate adds core nested-menu disclosures, optional utility/sticky/CTA settings, shared narrow/wide/full containers, grid/row/stack/media compositions and fluid semantic type roles. See [header/navigation](../header-navigation.md) and [layout/typography](../layout-typography.md). Both plugin version increments follow the existing lockstep packaging contract; their runtime behaviour and updater protocol are unchanged.

## Publish after review

1. Review/merge the v0.5.0 preparation PR and verify all CI jobs on the resulting main commit.
2. Tag that exact verified commit `v0.5.0`. The existing release workflow must create a prerelease, not stable/latest.
3. Confirm exactly `greendawn-0.5.0.zip`, `greendawn-core-0.5.0.zip`, `ezhost-updater-0.5.0.zip`, `updates.json` and `checksums.sha256`, with checksum/component validation passed.
4. Retain the installed v0.4.1 ZIPs and a staging backup. On staging only, update all three existing `candidate_tag` pins to `v0.5.0`; preserve the working database credentials, salts, repository allowlist and private token.
5. Use Dashboard → Updates to verify that all three native updates are offered and installed. Record their displayed versions.

## Focused hosted acceptance

Use the existing representative staging post and a temporary test page with saved core blocks and hosted media. CI's demonstration pages, brand plugin and localhost illustration are not deployed. Do not copy their localhost media URL into staging. Use the same page/canvas width when comparing fluid typography.

- [ ] A core primary menu with at least two nested levels: parent links still navigate, separate disclosure buttons open each level, and the current page is identified.
- [ ] Desktop Menu toggle stays hidden; mobile/tablet Menu opens inline. Test mouse/touch, Tab/Shift+Tab, Enter/Space, Escape and focus return. Leaving/clicking outside navigation closes disclosures.
- [ ] Resize across the mobile breakpoint while menus are open: no hidden focused link, stale open state, trapped focus or stuck scrolling. With JavaScript disabled, all nested links remain available.
- [ ] Assign an optional Utility menu. Under Appearance → Customise → Header, save a CTA label/destination and sticky setting, reload and verify persistence. Test the sticky header logged in, in a short viewport and while scrolling an expanded mobile menu. Restore intended defaults/configuration afterwards.
- [ ] A reading-width section, a wide group and a full-width coloured section: the full section spans the viewport while inner text stays contained. Check existing posts, archives/search and comments as well.
- [ ] Saved groups using grid/row/stack/media classes: three cards, wrapping links, a vertical stack and a hosted image beside copy. Confirm sensible stacking, gaps and preserved content in the editor and frontend.
- [ ] Heading hierarchy/type roles, long headings/addresses, tables, preformatted text and the existing quote/code/pullquote sample remain readable. Explicit block font-size settings still apply.
- [ ] Test at 320px, tablet and desktop widths, then native browser zoom at 200% and 400%. No unintended page overflow, clipped content, inaccessible menus or lost controls.
- [ ] Make a temporary text edit, save, verify publicly, revert and save again. Reopen the saved content without invalid-block warnings.
- [ ] Run the read-only hosted staging smoke workflow and inspect PHP/browser logs for errors. It does not exercise authenticated settings or certify visual parity.
- [ ] Rehearse file rollback to the retained v0.4.1 ZIPs without uninstalling components or restoring the database. Verify frontend/admin, then reinstall/update to the same v0.5.0 candidate through native updates.

Record results and any failures before continuing the footer. A correction uses a new reviewed candidate version; do not overwrite a published tag or its assets. Stable promotion remains a separate explicit approval through the existing promotion workflow after the candidate passes acceptance. Keep v0.4.1 stable until then.
